Nº 08

Why does the page scroll, behind your popup?

Scroll to the end of a list inside a modal or bottom sheet and the scroll passes on to the page underneath (scroll chaining). overscroll-behavior: contain on the popup's scrolling element stops the scroll at its edge, so the page stays put. It only applies to an element that actually scrolls.

Nº 07

Why does your page jump when you tap a link?

An in-page link teleports the page by default: no motion, so people lose their place. scroll-behavior: smooth on the root makes the browser glide to the section. Wrap it in a prefers-reduced-motion query so anyone who turns motion off keeps the instant jump.

Both boxes get the same jump to Pricing. With motion turned off on your device, the right box jumps too, as it should.

@media (prefers-reduced-motion: no-preference) {
  html {
    scroll-behavior: smooth;
  }
}

Nº 06

Why does your headline break so badly?

When a heading wraps, the browser fills each line as far as it can, so one word can end up alone on the last line. text-wrap: balance makes the browser even out the line lengths instead. It works on headings up to six lines in Chromium (ten in Firefox), so use it on titles, not paragraphs.

Before
A website that works as hard as you do
text-wrap: balance
A website that works as hard as you do

Narrow the window to see it on different widths: the left heading keeps leaving words alone, the right one stays even.

h1, h2, h3 {
  text-wrap: balance;
}

Nº 05

Why does your animation stutter?

Animating left (or width, top, margin) makes the browser redo layout and paint on every frame; miss the ~16.7 ms frame budget and frames drop. Move it with transform: it is handled in compositing, so layout and paint are skipped. Opacity works the same way.

Animating left
Animating transform

The button also keeps the page busy, like a heavy app does. The left box can only move when the page has a moment; the transform box keeps moving.

/* stutters: layout and paint on every frame */
@keyframes slide-left {
  to { left: 240px; }
}

/* smooth: compositing only */
@keyframes slide {
  to { transform: translateX(240px); }
}

Nº 04

Why does your list feel so flat?

When every row runs the same entrance at the same moment, the list lands as one block. Keep the animation and delay each row by its index, and the eye reads it top to bottom.

Before
Staggered
.row {
  animation: rise .45s ease-out both;
  animation-delay: calc(var(--i) * 40ms);
}

<!-- one index per row -->
<li class="row" style="--i: 0">…</li>
<li class="row" style="--i: 1">…</li>

Nº 03

Why does your popup just snap in?

CSS doesn't run transitions when an element goes from display: none to shown, so the popup appears on a single frame. @starting-style gives it a first state to animate from, so it glides in. No JavaScript.

With @starting-style

.popup {
  transition: opacity .3s, transform .3s;
}
.popup.open {
  display: block;
}
@starting-style {
  .popup.open {
    opacity: 0;
    transform: scale(.9);
  }
}

Nº 24

Why does your button feel dead on tap?

A button with no :active style gives no sign a tap landed, so people tap again. A short transition on scale and scale: .96 while :active make it dip under the finger and spring back (MDN :active, scale). Safari on iOS only applies :active when the page has a touchstart listener, so add ontouchstart to <body> (BCD note).

No :active
:active { scale: .96 }

Press and hold each button. The left one gives no sign the tap landed; the right one dips under your finger and springs back when you let go.

.btn {
  transition: scale .12s;
}
.btn:active {
  scale: .96;
}
/* iPhone: <body ontouchstart> */

Nº 19

Why does your dark page flash white?

Until a page's CSS loads, the browser shows a blank page in its default colors, which are light, so a dark site flashes white on every tap. The color-scheme meta tag, placed in the head before any CSS, tells the browser up front that the page supports dark; MDN says it helps prevent unwanted screen flashes during the page load, and it also turns default form controls and scrollbars dark. Chrome 81, Firefox 96, Safari 12.1.

no color-scheme
color-scheme: dark

Both panes have the same dark background and the same unstyled form controls. The left keeps the browser's default light colors; the right says color-scheme: dark, so the boxes, checkbox and menu follow the dark page. On a whole site, the meta tag in the head does this before any CSS loads, which is what stops the white flash between pages.

<meta name="color-scheme"
      content="dark light">

Source: MDN, <meta name="color-scheme">

Nº 18

Why does your thumb hit the wrong link?

Links set in small text are only as tall as their line, about 16 px, so one fingertip covers two of them. A block link with min-height: 44px gets a real target while its text keeps its size. WCAG asks for at least 24 x 24 CSS px (2.5.8, AA) and 44 x 44 for AAA (2.5.5), per MDN's Understanding WCAG.

Nº 17

Why does your form show the wrong keyboard?

A plain text field gets the standard keyboard for the user's locale (inputmode="text" is the default, MDN), so a code or PIN field opens letters and the user has to hunt for the digits. inputmode="numeric" asks the phone for a numeric keyboard with the digits 0-9. It changes only the keyboard, not validation.

No inputmode (text)
inputmode="numeric"

Open this on a phone and tap each field: the left one opens the letter keyboard, the right one opens a number pad. inputmode only changes the keyboard, not what the field accepts.

<input inputmode="numeric">

Nº 16

Why does one long name break your card?

The name has text-overflow: ellipsis, but it sits inside a flex item whose min-width is auto. MDN: for a flex item that minimum is its min-content size, so with white-space: nowrap the item can never be narrower than the whole name, and it pushes the button out of the card. min-width: 0 on the flex item lets it shrink, and the ellipsis shows. Every current browser.

.who { min-width: auto }
Maximiliana Okonkwo-Vandenberg
Pay
.who { min-width: 0 }
Maximiliana Okonkwo-Vandenberg
Pay

Both names have text-overflow: ellipsis. On the left the flex item can't shrink below the whole name, so Pay is pushed out of the card. On the right min-width: 0 lets it shrink, and the name ends in dots.

.who {           /* the flex item */
  min-width: 0;  /* may shrink below its content */
}
.name {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}

Why is your heading hiding under the header?

A link to #section scrolls its target to the top of the page, where a fixed header covers it. scroll-padding-top on the scroll container (html for the page) marks that top strip as covered: MDN calls it the offset of the optimal viewing region, used to exclude parts obscured by fixed toolbars. Every link jump then stops below the header. Chrome 69+, Firefox 68+, Safari 14.1+.

Nº 14

Why did your sticky header stop sticking?

A sticky element sticks to its nearest ancestor with a scrolling mechanism, and overflow: hidden creates one even if that box never scrolls (MDN position). So a wrapper with overflow: hidden captures the header and it scrolls away with the page. overflow: clip still clips, but the box is not a scroll container (MDN overflow), so the header sticks to the page again. Chrome 90+, Firefox 81+, Safari 16+.

.wrap { overflow: hidden }
FERNLY
.wrap { overflow: clip }
FERNLY

Both headers are position: sticky; top: 0. On the left the wrapper's overflow: hidden makes it the box the header sticks to, so the header scrolls away. On the right overflow: clip is not a scroll box, so the header stays. (Needs Safari 16+.)

.wrap {
  overflow: clip; /* was: hidden */
}
.header {
  position: sticky;
  top: 0;
}

Source: MDN, position: sticky

Nº 13

Why does your page slide sideways on phones?

Text only wraps at normal break points such as a space (overflow-wrap: normal, MDN), so a long link, email or code has nowhere to break: it sticks out past the screen and the page can be dragged sideways. overflow-wrap: anywhere lets that one string break at any point, only when it would overflow, and (unlike break-word) it also lets a flex or grid item shrink.

overflow-wrap: normal (default)

Nº 12

Why do your photos look squashed?

An <img> is object-fit: fill by default (MDN: the initial value), so it fills its box exactly and is stretched whenever the box has a different shape from the photo. object-fit: cover keeps the photo's own ratio, still fills the box, and crops the edges that don't fit; object-position picks which part stays in view.

object-fit: fill (default)
object-fit: cover

Tap the button: both boxes go wide, then tall. The left photo stretches to match the box; the right one keeps its shape and crops the edges.

img {
  object-fit: cover;
}

Source: MDN, object-fit

Nº 11

Why is your button cut off on phones?

100vh is the large viewport: the height with the mobile browser's bars retracted (MDN: vh is equivalent to lvh). While the bars are showing, as they are when the page first loads, the bottom of a 100vh hero sits under them, and so does its button. 100dvh, the dynamic viewport height, follows the bars, so the hero fits what you can see. dvh changes as the bars move while scrolling; 100svh is the stable size that is always fully visible.

height: 100vh
height: 100dvh
100vh
100dvh

Open both on a phone with the browser bars showing: the 100vh screen can put its bottom button under the bars; the 100dvh one fits what you can see. On a laptop both look the same.

.hero {
  height: 100dvh;
}

Source: MDN, viewport units

Nº 10

Why does your button stay lit after tapping?

On a touchscreen there is no pointer resting on the page, so mobile browsers emulate hover on tap, and depending on the browser the :hover style can stay on after the finger lifts, until the user touches something else (MDN). Put hover styles inside @media (hover: hover): only devices whose main input can really hover (a mouse, a trackpad) get them, and on a phone a tap is just a tap. A few Android devices report hover wrongly, so add and (pointer: fine) if you need to be sure, and keep an :active style for tap feedback.

Plain :hover
Inside @media (hover: hover)

Open this on a phone and tap both buttons: the left one can stay lit after your finger lifts, until you tap somewhere else; the right one only presses. With a mouse both light up on hover.

@media (hover: hover) {
  .btn:hover {
    background: #fff;
  }
}

Source: MDN, hover media feature

Nº 09

Why do your numbers wiggle when they change?

Most fonts use proportional digits: a 1 is narrower than a 0, so a live timer, price or score shifts sideways whenever a digit changes. font-variant-numeric: tabular-nums switches to the font's tabular figures, where every digit has the same width, so the number holds still. The font needs tabular figures (OpenType tnum); most UI fonts have them.

Proportional digits
10.00sec
font-variant-numeric: tabular-nums
10.00sec

Watch the word "sec": on the left it shifts every time a digit changes; on the right it holds still. (Some fonts already use tabular digits by default; the left side forces proportional ones so you can compare.)

.timer {
  font-variant-numeric: tabular-nums;
}

Nº 06

Why does your headline break so badly?

When a heading wraps, the browser fills each line as far as it can, so one word can end up alone on the last line. text-wrap: balance makes the browser even out the line lengths instead. It works on headings up to six lines in Chromium (ten in Firefox), so use it on titles, not paragraphs.

h1, h2, h3 {

Nº 05

Why does your animation stutter?

Animating left (or width, top, margin) makes the browser redo layout and paint on every frame; miss the ~16.7 ms frame budget and frames drop. Move it with transform: it is handled in compositing, so layout and paint are skipped. Opacity works the same way.

Animating left
Animating transform

The button also keeps the page busy, like a heavy app does. The left box can only move when the page has a moment; the transform box keeps moving.

/* stutters: layout and paint on every frame */
@keyframes slide-left {
  to { left: 240px; }
}

/* smooth: compositing only */
@keyframes slide {
  to { transform: translateX(240px); }
}
